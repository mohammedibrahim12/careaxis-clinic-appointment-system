Abstract and Table of Contents

01

Abstract

CareAxis is a full-stack clinic appointment platform created to replace manual booking registers and fragmented scheduling practices with a centralized digital system. The application uses React for the user interface, Express and Node.js for backend APIs, and MongoDB for persistent storage. It includes JWT-based authentication, role-based permissions, doctor profile management, appointment validation, dashboards, and case-oriented workflow support.

The project is fully suitable for academic use because it demonstrates practical MERN concepts without relying on paid APIs, payment gateways, cloud storage, or third-party communication services.

Foundation

Introduction, Problem Statement, and Objectives

02

Introduction

Small clinics often depend on notebooks, calls, spreadsheets, and informal staff coordination to manage appointments. As patient volume grows, this manual workflow creates delays, confusion, and avoidable booking conflicts. A digital appointment platform can improve the quality of clinic operations while also reducing the administrative burden on staff.

CareAxis addresses this challenge by providing a centralized web application for administrators, doctors, and patients. Each role sees only the features required for its tasks, making the system simple, secure, and efficient.

Problem Statement

  • Manual appointment handling causes booking errors and double scheduling.
  • Doctor availability is difficult to verify in real time.
  • Patients do not have a clear self-service booking workflow.
  • Clinic staff lack a single dashboard for monitoring appointment status.
  • There is no structured role-based system for tracking consultation progress.

Main Objective

Build a practical MERN application that digitizes clinic scheduling and workflow management.

Academic Value

Demonstrate authentication, CRUD, dashboards, validation, schema design, and role-based routing.

Zero-Cost Constraint

Run locally with MongoDB Community Server and avoid paid APIs or cloud dependencies.

Specific Objectives

  • Provide secure login for admin, doctor, and patient roles.
  • Allow admin users to create and manage doctor accounts.
  • Enable patients to browse specialists and request appointments.
  • Prevent duplicate bookings for the same doctor and slot.
  • Allow doctors to confirm, complete, or cancel appointments.
  • Present dashboard summaries for each role.

Existing Manual System

  • Appointments are written in registers or managed over phone calls.
  • Doctor schedules are coordinated manually by staff.

System Architecture

Three-Layer MERN Application Flow

React Frontend

Public pages, protected dashboards, forms, doctor listing, appointment views, and charts.

Express REST API

Authentication, doctor management, appointment validation, dashboard aggregation, and access control.

MongoDB Database

Stores users, doctor profiles, appointment records, status history, and timestamps.

Included in Scope

Registration, login, role control, appointment booking, doctor management, and analytics dashboards.

Excluded from Scope

Case Study

Workflow Analysis and Real-World Scenario

06

Case Background

Consider a small neighborhood clinic with one administrator, several doctors, and a growing number of patients. Previously, the clinic managed appointments using calls, handwritten notes, and informal staff coordination. This resulted in delays, missed updates, and difficulty tracking the status of consultations.

Admin Setup

The administrator creates doctor accounts with specialization, fee, and weekly availability.

Patient Registration

The patient creates an account and opens the doctor directory.

Appointment Request

The patient selects a doctor, a valid future date and time, and enters the reason for consultation.

Validation

The system verifies doctor existence, future date, availability window, and slot uniqueness.

Doctor Action

The doctor reviews the queue, adds notes, and updates status to confirmed, completed, or cancelled.

Admin Monitoring

The administrator tracks totals, trends, recent bookings, and doctor performance.

Illustrative Scenario

Riya Sharma logs in as a patient and chooses Dr. Asha Menon for recurring headache and fever. She selects a future slot inside the doctor's published schedule. The application accepts the request only if the slot is free. Dr. Asha later confirms the booking and completes the consultation after the visit. The updated status then appears in the patient dashboard.

Case Outcome

  • No manual phone coordination is required for basic booking.
  • The clinic avoids duplicate scheduling.
  • Doctors get a clear queue view.
  • Patients can see appointment progress transparently.
